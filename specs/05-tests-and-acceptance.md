# 05. Тесты и итоговая приёмка

## Цель

## Автоматические тесты

Используй PHPUnit 11, классы `tests/Feature/*Test.php`, базовый `Tests\TestCase` и `RefreshDatabase`. `phpunit.xml` уже задаёт SQLite `:memory:`. Не используй рабочую SQLite-базу и не отключай observer ради успешного теста. Создавай данные через существующие модели: factories сейчас отсутствуют. Для отдельных сценариев делай минимальные фикстуры; seeder используй в отдельном интеграционном тесте.

| Область | Обязательные сценарии |
| --- | --- |
| Идентификация | Нет заголовка, некорректный ID, неизвестный мастер → 401; ping работает без заголовка |
| Валидация | Нет `code`, null, массив, пустая/слишком длинная строка, неизвестный и собственный код → 422 |
| Привязка | Первая → 201; повтор → 200; другой допустимый код не перепривязывает; неизвестный/собственный код при существующей привязке → 422 |
| Безопасность данных | ID из тела не подменяет текущего мастера; чужие рефералы и начисления не попадают в GET |
| Список | Поля и типы соответствуют контракту; дата ISO 8601; стабильный порядок; пустой список |
| Сводка | Пустые нули; отдельные суммы pending/paid; total включает оба; rewarded определяет counted_referrals |
| Платежи | Первый положительный card и отдельно sbp начисляют; повторный платёж не начисляет; promo/trial не начисляют |
| Необычные правила | card на 0 сам не начисляет и блокирует последующий положительный card; promo/trial до первого положительного card не блокируют его |
| Размер награды | 3000 × 10 = 30000; изменение конфига влияет на новые начисления, но GET не пересчитывает сохранённые |
| История | Платёж без привязки не начисляет; attach не пересчитывает старые платежи; наличие старого card/sbp учитывается при следующих платежах |
| Целостность | Уникальность приглашённого и начисления; не остаётся частично обновлённого состояния при сбое записи |
| Демо | 6 мастеров, 4 привязки; только Ира rewarded; сумма Маши 30000, pending 30000, paid 0, counted_referrals 1 |

Не требуй конкретного текста стандартных сообщений Laravel, если он не закреплён контрактом. Проверяй HTTP-код, ключи ошибок и состояние БД. Не добавляй формальный процент покрытия ради числа.

## Проверка окружения

После настройки чистого окружения по этапу 03 выполни:

```bash
docker compose config
docker compose exec app composer check-platform-reqs
docker compose exec app php artisan route:list
docker compose exec app vendor/bin/phpunit
docker compose exec app composer docs
curl -fsS http://localhost:4400/api/ping
curl -fsS -H 'X-Master-Id: 1' http://localhost:4400/api/referrals/my
curl -fsS -H 'X-Master-Id: 1' http://localhost:4400/api/referrals/earnings
curl -fsSL http://localhost:4400/docs -o /tmp/referral-docs.html
curl -fsS http://localhost:4400/docs.postman -o /tmp/referral-postman.json
curl -fsS http://localhost:4400/docs.openapi -o /tmp/referral-openapi.yaml
```

Разбери выгрузки подходящим парсером и проверь содержание, а не только HTTP 200. POST вручную проверяй после исходной демо-сводки, поскольку привязка Лены изменит список Маши. Первый и повторный POST должны возвращать 201 и 200; новых начислений не появляется. Сброс допускается только в явно выделенной одноразовой БД.

Перезапусти Compose обычными `down` и `up -d`: данные, ключ и работа API должны сохраниться. Проверь генерацию документации повторно и убедись, что она не создаёт привязки или начисления.
