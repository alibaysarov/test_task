# 04. Документация Scribe и экспорт в Postman

## Цель и зависимости

После этапов 01–03 сделать `docker compose exec app composer docs` рабочим способом генерации HTML, Postman Collection и OpenAPI. Scribe уже есть в `require-dev`, а script `docs` уже вызывает `php artisan scribe:generate`: сохрани этот интерфейс.

Прочитай фактическую версию из `composer.lock`, установленный конфиг и поддерживаемые аннотации пакета. Не копируй настройки от другой версии Scribe.

## Реализация

- Опубликуй/создай `config/scribe.php` на основе установленной версии. Выбери режим выдачи документации через Laravel и обеспечь доступность `/docs`, `/docs.postman`, `/docs.openapi` в Nginx. HTML допускает redirect на канонический URL.
- Включи генерацию Postman и OpenAPI; ограничь документируемые маршруты публичным ping и тремя реферальными endpoints. Не включай внутренние маршруты самой документации.
- Сгруппируй endpoints: «Проверка сервиса» и «Реферальная программа». Дай короткие русские описания параметров, ошибок и правил начисления.
- Для реферальных endpoints опиши обязательный `X-Master-Id`, пример `1`, а также `Accept: application/json`; для POST добавь `Content-Type: application/json` и обязательный строковый `code` с примером `MASHA10`.
- Не представляй заголовок мастера как Bearer-токен. Укажи, что это заглушка идентификации. Ping и экспорт документации доступны без неё.
- Опиши точные схемы из этапа 02: успешные 200/201, 401, 422 с validation errors, пустые списки и нулевую сводку. Укажи целочисленные суммы и ISO 8601 даты.
- Генерация не должна отправлять изменяющий POST в рабочую БД. Предпочти явные примеры ответов и отключение response calls для изменяющих запросов; если используешь другие response calls, обеспечь отдельную тестовую БД. До и после генерации количество привязок и начислений должно совпадать.
- Проверяй примеры тестами API: они не должны маскировать неработающий endpoint. У Иры начислено `30000`, у Даши — `0`, итог Маши — `30000`.

## Требования к Postman

Коллекция должна импортироваться как Postman Collection v2.1 и содержать все четыре endpoints с правильными методами и телом POST. Запросы используют одну переменную `baseUrl`, без дублирования `/api` и без внутренних Docker-адресов `app`/`nginx`. Значение по умолчанию — `http://localhost:4400`; его можно менять в Postman.

Используй поддерживаемые настройки/расширения генератора; не полагайся на ручное редактирование выгрузки после каждого запуска. Заголовок `X-Master-Id` должен редактироваться; для первого успешного attach в демо-наборе используй `2` (Лена), для GET — `1` (Маша). Ясно укажи это в описаниях запросов.

## README и приёмка

Документируй генерацию, три URL, импорт коллекции по URL и из файла, настройку `baseUrl` и повторный импорт после регенерации. Укажи реальные пути файлов, полученные от установленного Scribe, не предполагаемые пути.

Проверь `composer docs` внутри контейнера, HTTP-доступность HTML и обеих выгрузок, валидность JSON коллекции и структуры OpenAPI, наличие методов, заголовков и схем. Запусти запросы коллекции через Postman/Newman, если доступно; иначе проверь соответствующие запросы через curl и честно отметь, что GUI-импорт не проверен. Проверь повторную генерацию без изменения БД. Генерируемые артефакты не коммить; конфигурацию, аннотации и поддерживаемые исходники документации сохраняй в Git.
